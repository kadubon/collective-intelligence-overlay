# 0.4.2 confirmation preparation

This is a prospective design note, **not a pushed confirmation preregistration**.
The second and final allowed E/M calibration cohort is complete and verified
offline. Its frozen 93-file source remained unchanged during inference.
Confirmation inference has not started. The [actual calibration report](studies/accumulation-042/calibration-v2/report.en.md),
[analysis](studies/accumulation-042/calibration-v2/analysis.json) and
[review provenance](studies/accumulation-042/calibration-v2/review-provenance.json)
retain the pooled gate pass separately from the insensitive family review.
The final JSON protocol and exact installed candidate wheel will be committed and
pushed before any confirmation request.

The operational question is whether retained executable experience improves
future quality or formation cost, and whether checked CIO state adds value over
strong ordinary shared skills. The primary endpoint remains the final fixed
checkpoint quality difference C minus M. Neither task selection nor stopping may
depend on that difference's sign.

The following reader/runtime corrections are implemented after calibration:
exact ordered stock reconstruction; checkpoint-before-learning identity;
declared family-wire validation without default completion; lazy optional Ollama
import; authenticated copy/qualification lineage; and exact installed package
bytes/import origins. Original calibration records and frozen code remain intact.

The installed-byte helper has passed an isolated actual candidate-wheel probe
and its changed-file/source-shadow negative checks. uv's local installation
metadata retains a supplied hash in its file URL fragment rather than filling
`archive_info.hashes`; both explicit representations are checked, with complete
package-byte comparison. Install the eventual tested wheel through a local file
URL containing `#sha256=<registered digest>` so its provenance is explicit. This
initial probe used an earlier candidate whose source/native gate was incomplete
and installed no runtime dependencies; it is not the required final installed gate.
A later clean installed runtime verified all 86 final wheel package files and
36 loaded executable modules. The real `adapters` namespace now requires the
standard namespace loader and one archive-backed location. Four actual peer
startup observations and reconstruction after provider termination passed in
a deterministic PG/OPA/TLS/A2A test with zero model requests. The complete native
gate is still required before confirmation.

Whole-pool foreign type/size matching alone is insufficient for a placebo. The
confirmation design will also check the family, public contract, version, count
and cognitive byte dose actually retrieved for each paired task. Genuine foreign
procedures retain their original schema, coefficients, source world and bindings.
Missing or empty matched state stays in every denominator; a nonidentifying
placebo contrast is unjudged. The same independent final checker applies to all
arms. Unperformed I/A panels leave H_SHARE/H_ADAPT unjudged.

A prospective two-budget panel will evaluate fresh forms of the same six
family/difficulty contracts with one and two allowed model drafts. The original
fixed anchor panel remains the primary endpoint. Full/empty interventions have
the same public forms, seed and per-offer budget; extra unused budget is not spent
on no-ops. This panel does not replace the output limit with truncation or move
the primary endpoint to the best observed checkpoint or budget.

The intended feasible design is three new independent worlds and all E/M/C arms,
with a complete three-position Latin order. The final finite request/token/wall
caps will use the valid pilot costs and complete prospective offer count. Three
worlds are an explicitly limited-power host study, not enough evidence to resolve
a five-percentage-point population difference. Task, peer, checkpoint and repeated
draft rows do not increase the independent N. No third calibration cohort or
p-value-dependent extension is allowed.

The [432-scenario precision plan](studies/accumulation-042/confirmation-precision-planning-v2.json)
records its source, NumPy/SciPy versions, 4,000 repetitions per scenario and
simulation seed. The [seed inventory](studies/accumulation-042/confirmation-seed-separation-v1.json)
found no overlap between 427319/619843/953117 and prior saved protocol seeds.
The [actual runtime contract](studies/accumulation-042/runtime-contract-v2.json)
was observed using seven bounded metadata calls and zero generation requests;
its [review](studies/accumulation-042/runtime-observation-review-v1.json) records
physical cleanup. These files are planning inputs, not confirmation results.
The [offline projection review](studies/accumulation-042/runtime-projection-review-v2.json)
confirms identical contracts from original and public metadata. Home-path
normalization retains every blob name, directive, model setting and other
metadata; the original full API response hashes remain separate. The earlier
full-show-hash contract is retained as a superseded planning input.

Quality MCID 0.05 represents at least one additional correct task per twenty
similar business tasks. A 20% complete cost improvement would be material only
at adequately comparable quality and with the relevant cost dimensions measured.
API fees, tokens, observed wall, reserved allowance and sampled CPU are separate
units. Missing energy/GPU/shared-service compute is unavailable. A token-only
conditional break-even calculation cannot establish the complete-cost claim.

Formation reporting will retain success and every failed finite-policy attempt.
For time/resource to first verified success, failure is an infinite event time
restricted to a fixed finite endpoint horizon; that endpoint penalty is separate
from actual observed consumption. This is a finite-policy restricted mean, not a
Kaplan-Meier estimate that assumes noninformative censoring. Report marginal
formation cost separately from initial setup, training, sharing and maintenance
investment. Experimental foreign-control construction and checkpoint measurement
remain visible as separate overhead. Nested call/arm/cohort wall observations are
not added, and shared model startup/load is not charged repeatedly.

The final protocol will fix the performed quality contrast family and conservative
simultaneous interval alpha, retain world-level bootstrap and distribution-free
bounds, and mark degenerate bootstrap intervals unavailable. Formation time,
resource, family/stratum, transfer, drift and frontier summaries remain descriptive
unless explicitly registered for inference. Precision simulation must distinguish
testing a positive effect against zero from proving an effect exceeds the MCID.
An insensitive family or stratum is reported even if its pooled score lies in the
calibration target band.

Occasional independent validation/Git work ran during calibration on the same
host. Pilot timing is descriptive planning information with that limitation.
Confirmation will avoid concurrent local validation. Original OS sampling begins
before the owned model server; CPU/RSS lower-bound coverage and unavailable
energy remain explicit.

Scientific figures use an isolated report environment with Matplotlib 3.10.8 and
NumPy 2.5.3; no new package runtime dependency is introduced. Matplotlib's published
metadata declares its PSF-based license and Python >=3.10
([version-specific distribution](https://pypi.org/project/matplotlib/3.10.8/)).
Report rendering is downstream of offline verification and analysis; it never
sends a model request or substitutes layout tests for observed study results.
